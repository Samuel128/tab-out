02 / File handoff

How Clash reads your list.

Clash never reads the Tab Out form directly. The local helper saves your input, generates a provider file, then tells Clash to reload and verify it.

03 / YAML → Clash

Register and use

The active Clash configuration registers that local file as rule-providers.need-proxy, then sends matches to PROXY.

rule-providers:
  need-proxy:
    type: file
    behavior: classical
    format: yaml
    path: …/tab-out-need-proxy.yaml
rules:
  - RULE-SET,need-proxy,PROXY
✓

After every change, the helper reloads the active Clash configuration, refreshes need-proxy, and compares the loaded rule count with the saved list. Only then does Tab Out show Applied; if Clash is unavailable, it shows Pending instead.

03 / Decision path

First matching rule wins.

01

Company traffic stays direct

Protected processes and internal domains come from a local private file and precede the proxy list. This domain is only an example.

DOMAIN-SUFFIX,internal.example,DIRECT
02

Your list goes to PROXY

The need-proxy provider contains the domains you manage in Tab Out. Its match types become DOMAIN-SUFFIX, DOMAIN, or DOMAIN-KEYWORD rules.

RULE-SET,need-proxy,PROXY
03

Everything else goes direct

If no earlier rule matches, Clash uses DIRECT. Removing a domain from Tab Out does not block the site; it returns to direct routing.

MATCH,DIRECT
↻

What the status means

Applied means Clash accepted and verified the rule-provider count. Pending means the list was saved but Clash was unavailable; retry when Clash is running.

↗

Two kinds of direct

With macOS system proxy enabled, a request may still enter local Clash first and then exit via DIRECT. Bypassing Clash entirely requires a separate PAC or system-proxy setup.
